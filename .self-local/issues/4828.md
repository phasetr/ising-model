## Summary

PR #4826 tracks the evidence an open issue rests on, so that a decision's basis is visible to
review instead of sitting in a gitignored directory. It could not track all of it. This
repository is public and `CLAUDE.local.md` requires committed artefacts to be English; **16
reports that a tracked issue mirror cites, or that PR #4826 had staged, contain Japanese and
were therefore left untracked**. This issue is the record of that gap, so it is visible rather
than silently absent.

Nothing here asks for the English-only rule to be relaxed.

## Consequence already visible: one dangling citation

`.self-local/issues/4823.md:11` names its design source of truth:

    Design SOT: `.self-local/reports/design-duplication-consolidation-2026-07-31.md`

Mirror `4823.md` is tracked by PR #4826; the report it cites is not, and is tracked on no
branch. So a reader of the repository can see issue #4823's mirror and cannot reach the
document it defers to. That citation is dangling until the report is translated.

This is also the selection-rule defect the review caught: PR #4826's rule was "track the reports
a tracked mirror cites", and this one was cited and dropped anyway. The rule now has a stated
exception (Japanese) rather than an unexplained omission.

## Content judgement wanted, separate from language

`handoff-2026-07-24-campaign-exhausted.md` (45 Japanese lines) narrates an internal incident:
an agent amended and force-pushed `main`, and the user ordered a rollback. Translating it would
make that account public along with everything else in the file.

**That is a decision for the user and not a language question.** Even if the file is translated,
it should not be tracked until the user has said whether the incident narrative belongs in a
public repository. Three outcomes are available — track it in full, track a redacted version, or
leave it untracked permanently — and this issue does not presume one.

## Recorded, deliberately not built

### The ratcheting citation check — now the only candidate mechanism

The source review proposed a roughly 15-25 line ratcheting check: *a tracked file must not cite
a `.self-local/` path that is untracked*, with a committed baseline count that may fall and
never rise. Its attraction is that it needs no manifest, no `gh` query and no human refresh —
the tree is its own input, so it cannot go stale.

It was originally recorded here as a *replacement* for V5, because the user had chosen V5 and
PR #4826 was shipping it, and building both would have meant two checks aimed at one property
with the weaker guarantee of each obscuring which one actually holds.

**That framing no longer applies. V5 was dropped in full at round 4, so there is nothing for
this check to replace and no check of any kind guards the property today.** The reasoning
recorded with the ruling: V5's remaining guarantee, after its postdating arm went at round 3,
was "every issue the manifest lists has a git-tracked mirror" — an index-presence check over a
hand-maintained list. It cannot see an issue the list omits, and it cannot see the list going
stale, so it could not have caught the failure that motivated the whole branch (#4794 was filed
asserting a question was unresolved three days after the answer had been posted, because the
deciding evidence was gitignored; nobody listed that issue and nobody tracked it). Shipping 654
lines for a design that already had a named successor recorded on this issue was judged not
defensible under a directive that puts simplification and debt reduction first.

The history of V5's two deleted staleness detectors is kept here because it is evidence about
this design space, not about a shipped artefact. The timer (round 2) made one commit's verdict a
function of the day it was evaluated. The mirror-ordering arm (round 3) charged any mirror on
disk numbered above the manifest's maximum; it was inert in CI for the case it advertised (a
clone holds only tracked files, so a newly written untracked mirror is not there to be found)
and it produced a false positive in CI in an ordinary case — when the highest-numbered issue is
no longer open and the manifest is honestly refreshed, the arm charges that issue's still-tracked
mirror, re-running the `gh` query does not clear it, and the only clearing move is
`git rm --cached` on the mirror, the opposite of what the branch exists to do.

**Whether to build the ratcheting check at all is the open question**, and it is the user's to
answer; the acceptance criterion below states it that way.

## Unclosed gap: Japanese is already tracked where no check looks

Review round 2 of PR #4826 named this as an asymmetry created by V5, which *compelled* commits
into `.self-local/issues/` while V4 — the Japanese/English-only check in the same script — does
not list `.self-local/` in `V4_PATHS` and deliberately must not, that directory being internal
working material.

**Dropping V5 removes the compulsion but not the gap.** Nothing now forces a commit into
`.self-local/`, yet 130 Japanese lines are tracked there today, and `V4_PATHS` still does not
look at them. The user's decision for PR #4826 was explicitly *track only English files* in a
public repository; tracking English-only additions while Japanese sits tracked already is half
of that policy, not all of it, and that is true whether or not a gate compels anything.

### Why PR #4826 does not act on it

Two candidate repairs exist and both are policy changes of their own, so neither was taken
unilaterally in a pull request already at the edge of proportionate scope:

- **Translate `INDEX.md` and the eleven others.** That rewrites a 1222-line ledger the whole
  session-resume procedure reads.
- **Extend `V4_PATHS` to cover `.self-local/`.** That would turn every one of the 130 lines into
  a hard gate failure on the next push, so it cannot land before the translation does, and it
  reverses a documented exclusion (`V4_PATHS` is currently documented as deliberately excluding
  this directory).

**This is for the user to decide**, and this issue presumes neither option. The gap is stated as
a known, unclosed one in PR #4826's body rather than left implicit.
