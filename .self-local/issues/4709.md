# Issue #4709: process — gate PR body against the actual diff before merge (nine incidents, two subclasses)

**Status**: OPEN

**Created**: 2026-07-25 (`dev-issue-manager`, recurrence-prevention proposal (c) from #4704, filed
as a separate process/tooling issue since it is not a docs/tex stale-reference item)

GitHub: https://github.com/phasetr/ising-model/issues/4709

## Problem

Four PR bodies in one session were factually wrong about their own diff: #4702, #4703, #4707,
#4708 (see GitHub issue body for details of each). No pipeline stage checks the PR body itself
against the diff it describes, yet squash-merge writes the body verbatim into `main`'s permanent
history.

## Proposed fix (as filed)

Mandatory gate before a PR leaves draft: re-derive every file/line-number/count/path/issue-PR
reference/closing-keyword the body asserts from `git diff <base>...HEAD`, and block draft-lift on
mismatch. `--body-file` must supply the squash-merge message explicitly.

## UPDATE 2026-07-25 (dev-pr-clerk) — structural gap found in the very next PR after filing

PR #4710 (opened immediately after #4709 was filed, to fix the `docs/index.md:1715` item under
#4704) is itself an instance of the same failure class this issue targets, **despite applying the
proposed gate**: an earlier draft of its body attributed the introduction of the three removed
`TransferMatrix/Layer*.lean` modules to commit `752f31ae`/PR #4228, which is false — `752f31ae`
only added the citing `docs/index.md` row and never touched the Layer* modules; the true
introduction commits are `ed70e3f5`/#4076, `88cb6027`/#4078, `6022207f`/#4079. (The body was
corrected before this comment was posted; current PR #4710 body states the correct provenance.)

At draft time, self-verification confirmed the commit-hash <-> PR-number correspondence
(`752f31ae` <-> #4228) but did not verify **what that commit actually did** in the tree.

**Structural gap**: the proposed gate re-derives assertions from `git diff <base>...HEAD`, i.e.
the *current PR's own diff*. A claim about which *past* commit introduced/removed some *other*
file is a provenance/history claim about a commit outside the current PR's diff by construction —
the gate as proposed cannot check it, regardless of how carefully it is applied.

**Proposed refinement**: history/provenance claims in a PR body ("commit X introduced/removed
path Y") must be verified against the actual content of that historical commit — e.g.
`git show --stat <hash>`, or `git log --diff-filter=A|D -- <path>` for true
introduction/removal points — not merely by confirming hash <-> PR-number correspondence.

**Error source**: the false provenance claim originated in a `dev-research` investigation report
and was transcribed into the PR body without the downstream drafting step re-verifying it against
the historical commit's actual content. This is a second, independent recurrence source distinct
from the four same-session incidents already logged on this issue: investigation-stage reports are
not automatically ground truth and must be re-checked against primary sources before being
transcribed into a merge-bound PR body, particularly for provenance/history claims.
