## Scope

### Cluster A — the `by_cases` exhaustion idiom (P-A1, P-A2)

The real debt is not the six magnetization twins but the hand-expanded
`by_cases A ⊆ Λ.volume n` idiom. Measured spread: `correlationAlongExhaustion_of_subset`
is referenced in **46 modules**, and `by_cases … ⊆ Λ.volume` appears **81 times** across
`IsingModel/`.

Remedy: two primitive function-equation lemmas in `AmbientLattice/Exhaustion.lean`,
`correlationAlongExhaustion_comp_of_subset` and
`correlationAlongExhaustion_comp_of_not_subset`, sited immediately after the pointwise
lemmas they generalise from a point to a family. Each call site collapses from about 13
lines to about 5.

The design **explicitly rejects** the shorter predicate-eliminator form
`(P : (α → ℝ) → Prop) → … → P (fun t => correlationAlongExhaustion …)`: `P` would be a
metavariable applied to a non-pattern argument, i.e. the `?m x` non-Miller-pattern shape
that this repository's own measurement identified as its single largest known build-time
sink (the `Meta.isDefEq` delta-descent cluster removed by PR #4716, whose cost is 100%
wasted on a *failing* unification path). The function-equation form is first-order and
elaborates by ordinary `rw`; `q` must be passed explicitly at call sites.

## Detection defect that must not be repeated

`tex/proof-guide.tex` escapes underscores inside `\texttt{...}` (`\texttt{a\_b}`), so a
plain `git grep -F "a_b"` returns **0 hits while the citation is present**.

On PR #4821 the implementer, the independent reviewer, **and** the codex cross-review all
concluded "tex cites 0 of the deleted names", and the PR body states that
`tex/proof-guide.tex` needs no change. Only a Tier-1 audit that normalised the escapes
found two real dangling citations. Reproduced here:

```
$ grep -c -F "spin_edge_supermodularJ" tex/proof-guide.tex            # 0
$ tr -d '\\' < tex/proof-guide.tex | grep -n -F "spin_edge_supermodularJ"
686:(texttt{spin_edge_supermodularJ}, 16-case check), and the nonnegative weights
$ tr -d '\\' < tex/proof-guide.tex | grep -n -F "latticeDistance_pair_eq_displacement"
26903:texttt{latticeDistance_pair_eq_displacement},
```

Both names are deleted by PR #4821, so both citations dangle.

**Standing rule to record: every deletion PR must run the normalised sweep
(`tr -d '\\' < tex/proof-guide.tex | grep -F <name>`, not a raw `git grep`) over every
deleted name, and must show the command and its output in the PR body.** Three independent
review channels agreeing on an un-normalised result is not evidence.
