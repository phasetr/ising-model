PR #4825 (`tooling/4792-fail-closed-terminal`), plus one observation about a test

was never measured.

## G2 (Low) -- an unknown TeX wrapper is fail-open and no canary forces it

`scripts/dead_candidate_scan.py:1009` (`_TEX_CODE_CMDS`). The span grammar reads
only `\texttt`, `\verb`, `\lstinline` and `\mintinline` in braced form. A name
written with any other wrapper, e.g. `{\tt caf\'{e}\_lemma}`, produces no span,
therefore no citation *and no coverage warning* -- the fail-open shape the parent
lane exists to remove.

State: pre-existing, untouched by PR #4825, and disclosed as limitation `L7b` in
the `--explain` table. Measured: **0** occurrences of `{\tt` in
`tex/proof-guide.tex`, so it is not live. The gap is that nothing keeps it that
way: unlike the line-break shapes, which `run_tex_canary` aborts on
unconditionally, no canary rejects an unrecognised wrapper in the real guide.

Disposition wanted: either add a canary that aborts when the guide grows a
code-like wrapper the grammar does not read, or record the editorial rule that
the guide uses `\texttt` only, with a check that enforces it.

## G3 (Low) -- the repaired `--lean` fatal condition may always fire

`scripts/dead_candidate_scan.py:2831`:

    if not text_consumers or verdict.verdict == NO_CITATION:

This is the F6 repair. The old condition was keyed on the `no-citation-found`
verdict alone, a bucket the fail-closed charging model empties, so the one hard
cross-check against the elaborated graph could never fire. The new disjunct fires
when the text scan attributed no consumer at all while Lean holds some.

The risk is the mirror image of "never fires": it may **always** fire. The
reviewer measured that **2,961 of 10,618** candidates have an empty
`text_consumers` set. The direction is fail-closed and therefore correct -- a
false hard failure costs a human look, a missed one costs a deletion -- but the
breadth is unmeasured, and `--lean` needs a green build, so no run has ever
exercised it on the real corpus.

Disposition wanted: run `--lean` once on a green build and record how many of the
2,961 actually reach the fatal branch (Lean must also hold consumers), then decide
whether the condition needs narrowing or whether the population is small.

## G4 (Low) -- the F5 guard has no permanent in-suite pin

F5 repaired `MutationMetaTest.run_witness`, which counted a nonexistent witness
name as "red" because `loadTestsFromName` turns an unknown name into a synthetic
failing test -- a mutation table that certified its own mutations without running
anything. The repair resolves the name in the module before running it.

The reviewer demonstrated that the guard works with a two-stage experiment:
misspelling a witness name **with** the guard is RED, and the same misspelling
**with the guard removed** is GREEN. That experiment is not committed, so nothing
in the suite makes the guard alone turn it red; a future edit that drops the name
lookup would be silent.

Note the contrast: the round-2 repair on this branch (the `--help` vocabulary
guard) did commit its permanent pin, as `MutationMetaTest` case `M9b`. The same
treatment is what F5 lacks.

Disposition wanted: a test that removes the name resolution from `run_witness` in
process, feeds it a nonexistent witness, and asserts the result is *not* counted
as red.

## Observation -- the deleted `ResolvedGlobElisionHeadTest` cost precision, not soundness

PR #4825 deletes `ResolvedGlobElisionHeadTest`. The reviewer checked its five
cases: four asserted the very exoneration the PR destroys (a resolved glob head
that charges a *selection* of its matches), and two referenced symbols the PR
deletes. Deleting the class was right.

One live property went with it: the elided head at `docs/index.md:1387` resolves
to exactly one declaration -- still true at head -- and that was the class's only
real-corpus endpoint. Its loss is a **precision** loss, not a soundness one: a
regression in that resolution now charges every candidate instead of one, i.e.
the tool gets stricter, never more permissive.

Disposition wanted: optional. If a real-corpus endpoint is wanted back, pin the
single-match property of `docs/index.md:1387` in `FamilyCalibrationTest`, where
the other corpus pins live.
