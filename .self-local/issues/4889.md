## Summary

Resolve four suspicious specialization import edges with compiler-backed evidence:
(1) `CubicMayerClusterFreeEnergyComplex -> LatticeBoundaryBED`;
(2) `LatticeFreeEnergyInfiniteKPBound -> NeighborDegree`;
(3) `PlusHighTempRepresentation -> CubicBoxScreening`;

REMOVE/REPOINT/KEEP with compiler+Shake evidence; do not manufacture a pass by changing Shake
ignore config; no touched module may gain a wider import closure.

## Resolution

Closed as completed. Edge 3's repoint cut the sole supply route of the anonymous
`Ambient.inducedGraph (latticeGraph d) Λ` `Fintype`/`DecidableRel` instances for 64 downstream
modules, requiring three remediation imports (`Conditioning/InduceDistanceTransfer.lean`,
`Peierls/DualSupport.lean`, `Peierls/PlanarBondSeparationBridge.lean`) — exactly the three named
in `lake exe shake`'s own `instead` list. This created one new `L2 -> L4` INFO edge
(`Conditioning.InduceDistanceTransfer -> Concrete.LatticeGraphBED.LatticeBoundaryBED`) replacing
the old `PlusHighTempRepresentation -> CubicBoxScreening` one, so the `L2 -> L4/L5` INFO edge
count stayed at 24 before/after (unranked, never fails the contract checker).

Follow-up (not actioned, no new issue filed): dev-implement flagged the anonymous-instance-
fragility pattern found in `Peierls/*` (transitive-import removal silently breaking
`Fintype`/`DecidableRel` instance resolution because the supplying instances are anonymous) as a
candidate for a future `dev-audit-tier2` finding.
