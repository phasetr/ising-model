# Issue #4822: [P1 tooling] Completion-claim gate rejects accurate PR bodies: directive-keyword and raw-HTML scans do not exempt code spans

**Status:** OPEN (filed 2026-07-31)

GitHub: https://github.com/phasetr/ising-model/issues/4822

Parent: #4796

Related: #4801 (the checker and fixture corpus in which the two scans live)

Root parent: #4786

## Summary

A defect **in** the control installed by #4796 / #4801, not a request to weaken it.

`scripts/completion_claim_gate.py` applies two whole-body scans to the NFKC-normalized PR
body before any structured validation, and neither excludes fenced code blocks or inline
code spans:

- `_reject_directive_keywords` (line 682) → `DIRECTIVE_KEYWORD_FORBIDDEN` for any
  standalone token of `close`/`closes`/`closed`/`fix`/`fixes`/`fixed`/`resolve`/
  `resolves`/`resolved` (`CLOSE_KEYWORDS`, lines 47-57 and 69-71). `_keyword_spans`
  (line 432) treats any non-ASCII-alphanumeric neighbour as a token boundary, so `-`,
  `_`, `.`, `/` all delimit.
- `_reject_raw_html` (line 690) → `RAW_HTML_FORBIDDEN` for a single `<` anywhere.

Both run on `_normalized_body_text(body)` at lines 795-797. The module already has fence
machinery (`FENCE_OPEN_RE`, line 81) that these scans do not use.

## Evidence (PR #4820)

PR #4820 is red on `completion-claim/live` with `OFFLINE_CHECK_FAILED`:
https://github.com/phasetr/ising-model/actions/runs/30642139316/job/91194495525

Local re-run of the two scan functions against the PR's current body reproduces both
`RAW_HTML_FORBIDDEN` and `DIRECTIVE_KEYWORD_FORBIDDEN`, with four keyword spans:

1. `fixed` inside the committed path
   `` `.self-local/reports/perf-4724-fixed-cost-reconciliation.md` `` — the file exists at
   that exact name on `origin/build-speed/4794-fixed-cost-protocol`, so **no accurate body
   citing it can pass**;
2. `closed` inside a quotation of the design document's own wording, in a sentence that
   then denies the claim;
3. `resolved` in `Deduplication is now by resolved path.`;
4. `close` in an explicitly **non**-closing sentence about the #4794 units question.

`RAW_HTML_FORBIDDEN` is triggered by one `<` in the code span
`` `git diff 04e22c26 -- <artifact>` ``.

Net effect: the gate currently forces bodies to be *less* accurate to pass, inverting the
intent of #4796.

## Proposed remedy (proposal, not decision)

Exempt fenced code blocks and inline code spans from both scans; keep the prose surface
fail-closed. The keyword rule itself must not be deleted — a prior incident had a closing
directive inside a negated sentence auto-close an issue.

## Process constraint

Must be fixed in its **own PR with its own independent review**, and not inside a PR whose
own red check it would turn green (that would be self-authorization). In particular not
inside PR #4820.

## Acceptance criteria

- [ ] Both scans are code-span / fenced-block aware; prose surface stays fail-closed.
- [ ] Regression fixture pins each of the four PR #4820 spans as passing in code-span /
      quotation position and failing in bare-prose closing-directive position.
- [ ] The negated-directive auto-close incident stays covered by an explicit fixture.
- [ ] Delivered in a standalone PR not dependent on its own fix for CI.
- [ ] PR #4820 can then cite the reconciliation report path verbatim and pass.
