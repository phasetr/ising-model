## 2026-07-13 META FINDING (dev-issue-manager governance note)

Both R6 (2026-07-13 downgrade) and R3 (2026-07-13 scope correction) independently show the
same failure mode: the **simplification-audit premise for a refactor issue was derived from
raw LOC counts / declaration counts and overstated the amount of true duplication**. In both
cases a `dev-design` re-audit found most of the flagged surface to be legitimately distinct
abstractions (different types/hypotheses/specializations), with only a small, genuinely
duplicated core actually warranting extraction/consolidation.

**Lesson for future refactor audits**: LOC/decl-count deltas between modules are not by
themselves evidence of duplication. Future `dev-audit-*` / `lean-refactoring` simplification
passes should judge candidate consolidation targets by **import dependency structure** (is
module B built on top of module A, or an independent copy?) and **type/hypothesis
isomorphism** (do the "duplicate" declarations actually state the same thing over
definitionally/propositionally interchangeable types?), not by LOC volume alone. Large LOC
in a downstream module is expected and healthy when it is genuinely built on, not
duplicating, an upstream module.
