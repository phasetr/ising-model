## Summary

`dev-perf` ran a **clean full build of all 2011 modules** in an isolated worktree at main
`4b14a205` (`lake build --no-ansi` -> 5040 jobs, wall 17:02, user CPU 4031s). This is the
first campaign to reach true 2011/2011 coverage; the two prior "exhausted" conclusions were
both wrong because they measured only 48/2011 modules selected by proxies (`maxHeartbeats`
markers, file line count) later shown uncorrelated with measured cost.

Two new outliers found (ranks 26-60 also own-cost measured, max 4.90s, confirming no other
outlier hides below the top-25):

1. **`IsingModel/ClusterExpansion/AlternatingCompleteGraph/CompleteGraphK4.lean:34`** —
   `decide` on a finite-enumeration goal. Repo's **slowest module** (clean-build wall
   22.0s, own-cost 11.64s, of which `decide` tactic 4.96s + kernel type-checking 3.63s =
   74%). A/B measured on a standalone copy: `decide` real 13.01s vs `decide +kernel` real
   7.74s = **VERIFIED -5.3s**. Fix stays plain `decide` (no `native_decide`).
2. **`IsingModel/PseudoMass/HLSCorrelationCapstone.lean:185,189`** — 2x `positivity` (rank
   3, clean-build wall 16.0s, own-cost 8.79s, of which interpreted `Positivity.evalDiv`
   2.84s + 2.71s = 63%). Needed hypotheses `hmxr_nn`/`hMdx_nn` already in context; proposed
   explicit-term replacement mirrors PR #4695/#4707. **Estimated -4..5s, NOT A/B measured**
   (goal needs full local context).
