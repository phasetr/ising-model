## Recurrence-prevention proposal (for consideration)
(a) Mandatory closing check on deletion-type PRs: `grep <deleted-decl-name> docs tex` = 0.
(b) `dev-review` audit_gate V1–V4 does not verify docs/tex-to-declaration correspondence
(the #4702 defect class: code deleted, docs left claiming Done); consider a V5 gate.
(c) **NEW (dev-issue-manager, 2026-07-25) — PR-body/claim verification gate.** In this session
alone, four consecutive PR bodies were factually wrong about their own diff: #4702 (a retraction
claim that the diff did not make), #4703 (stale `jobs` count), #4707 (inconsistent counts /
measured values), #4708 (body copied wholesale from #4706, including a wrong `Closes #4706`).
Root cause is structural, not personal: `dev-verify`, `dev-review` and `dev-audit-tier1` all
inspect *code / diff*; **no stage inspects the PR body against the diff**, yet the body is what a
squash merge writes into `main`'s permanent history. Proposed fix: add a body-vs-diff
reconciliation step to the merge gate — every file, line number, count, path, PR/issue reference
and closing keyword asserted in the body must be re-derived from `git diff main...HEAD` before
the PR leaves draft. This item needs its own tracking issue (it is a process/tooling defect, not
a docs/tex stale-reference item, so it does not belong to #4704's scope).
