## Evidence (corrected, `dev-research` + `dev-issue-manager`, 2026-07-25)
Full report: `.self-local/reports/research-4704-stale-refs-inventory.md`.

- A naive tokenizer over-counts massively in this repo because of two systematic doc-writing
  conventions: (1) common-stem shorthand, e.g. `foo_bar_baz`/`_qux`/`_quux` families with the
  shared stem elided, and (2) multi-file shorthand, e.g. `A/B/C/D.lean` denoting several real
  files sharing a filename prefix, not one path. Both are pervasive in `docs/index.md` and
  `tex/proof-guide.tex`.
- Filtering surviving "stale" identifier tokens against Mathlib/Lean4-core declaration names
  (~403k declarations) removes 42% of them (867 of 2064 unique tokens) as legitimate references
  to Mathlib/core API, not project stale references.
- **classification B (content silently deleted with no disclosure in the surrounding text, i.e.
  a hidden false "Done" claim) was found in ZERO cases** across the spot-checked sample (ray-exit
  archive, LatticeSystemBridge, Mayer order-3, the §17.1 Dobrushin paragraph). Every case where
  content is genuinely gone is a row that already discloses the removal in its own prose (e.g.
  "*archived*", "**Removed**"). **No keep-criterion (f) trigger was found.**
- The confirmed, concrete, mechanical classification-A (rename/move) count is **4 lines in
  `docs/index.md`** (1973/1974/1976/1979, see Update 2 above), fixed by PR #4708.
- `docs/index.md:1715` cited `TransferMatrix/Layer{DobrushinContraction, Doeblin,
  DoobSpectralGap}.lean`; none of the three files exist in the tree (verified 2026-07-25). Not in
  PR #4708; fixed separately by PR #4710 (see Scope item 1 below). The same three module names
  still appear in one `.lean` doc comment (see Scope item 2(a)) — not in scope for PR #4710.
- The remaining candidate pool (~1200 unique post-filter identifier tokens across both files,
  the tex file's 85 raw stale file-path tokens, and ~3195 tex identifier tokens) is **unclassified
  and unverified** — dominated by the shorthand/Mathlib false-positive patterns above, not yet

  premature and is explicitly **not recommended** until a lower-false-positive scanning method
  (semantic per-line triage, or a script that understands the shorthand conventions) is
